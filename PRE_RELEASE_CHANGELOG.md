# Pre-Release Changelog

## Unreleased

## Breaking Changes

- **AbortSignal cancellation reasons (v2):** HTTP, XHR, and Fetch cancellations now use a string message derived from `signal.reason` and retain the original arbitrary value as a non-enumerable `CanceledError.cause`. Symbols, BigInts, falsy values, cross-realm errors, and non-coercible objects cannot prevent transport cancellation. Each cancellation creates a fresh error with its own request context without mutating the supplied reason, so requests sharing a signal retain separate diagnostics. A supplied `CanceledError` contributes its existing own cause if present; otherwise the original error becomes the cause. Cancellation-shaped plain objects are normalized into real errors. Other `AxiosError` reasons are wrapped with `ERR_CANCELED`, including cancellation after HTTP response-stream delivery. A bare `controller.abort()` now exposes the runtime's default abort message instead of always `"canceled"`; use `axios.isCancel()` or `ERR_CANCELED` to detect cancellation. `AxiosError.cause` is now typed as `unknown` in both declaration formats and requires narrowing before use. The HTTP adapter ignores cancellation options inherited only from shared object prototypes and keeps the originally registered signal for abort reasons and listener cleanup. Configured request timeouts retain their existing error codes. (**#10946**, closes **#7434**)

- **Types - Fetch Options:** Validate known `RequestInit` fields in `fetchOptions` consistently for ESM and CommonJS consumers, excluding `body`, `headers`, `method`, and `signal`, which remain unchecked. Previously, the `Record<string, any>` union allowed invalid values such as `cache: 123` or `redirect: 'sideways'`. These now produce TypeScript errors; migrate to valid values such as `cache: 'no-store'` and `redirect: 'manual'`. Provider-specific fields such as Node's `dispatcher` and other custom fetch options remain accepted without casts or global augmentation. Fields added through global `RequestInit` augmentation, such as Next.js `next`, retain their declared types. Unknown property names remain allowed intentionally, so this does not catch every misspelled key. Runtime behavior is unchanged. (**#10961**)
- **Raw header parser dictionary (v2):** `axios/unsafe/helpers/parseHeaders.js` now returns a null-prototype dictionary. This retains an own `__proto__` header and prevents inherited getters or setters from interfering with parsing. Direct helper consumers must use `Object.prototype.hasOwnProperty.call(headers, name)` instead of inherited object methods and must not rely on `headers instanceof Object` or implicit object-to-string conversion. Duplicate-header rules are preserved, and normal `response.headers` remains an `AxiosHeaders` instance. This extends the own-property checks from #11036; it does not establish a prototype-pollution vulnerability from string-valued response headers. (**#7538**)
- **Node agent typings (v2):** Narrowed `httpAgent` and `httpsAgent` from `any` to Node 20+ agent instances or runtime-compatible agent dispatchers in both ESM and CommonJS declarations. TypeScript now rejects constructor-option, destroy-only, and state-only objects that Node cannot use as request agents. Runtime behavior is unchanged: `null` clears an instance's custom agent and selects Node's global agent, `false` selects a separate agent for the request, and `undefined` or omission preserves an instance default. (**#5492**)
- **Browser bundle syntax baseline:** Axios v2 keeps the existing browser ESM, CommonJS, and UMD artifact paths, including `dist/axios.js` and the jsDelivr/unpkg default `dist/axios.min.js`. The UMD files still support classic `<script>` loading, expose the global `axios`, and work with AMD/RequireJS, but all browser bundles now target ES2018 instead of transpiling UMD to ES5. Applications that require ES5 syntax should remain on the v1.x maintenance line or apply their own controlled transpilation and runtime polyfills. The release build now uses standalone Rolldown while the transitional CommonJS package surfaces remain available.
- **Node.js runtime baseline:** Axios v2 now requires Node.js 20 or newer. Applications that must run on Node.js 12, 14, 16, or 18 should remain on the v1.x maintenance line or upgrade Node.js. This change aligns package metadata, the Node build target, type fixtures, and compatibility workflows; the existing CommonJS artifacts remain available on Node.js 20+ until the separately planned ESM-only migration.

## Features

- **Response duration:** Added `response.duration` and `error.response.duration` when a response is available, with matching ESM/CommonJS types. The value measures wall-clock milliseconds from adapter invocation to settlement, excluding interceptors and request/response transforms. Buffered responses include body reception; streamed responses stop timing when the stream becomes available. Backward clock adjustments clamp to zero, while forward adjustments can inflate the value. Errors without a response have no duration. This additive API replaces any custom adapter's existing `duration` value with the dispatch measurement. (**[#11214](https://github.com/axios/axios/pull/11214)**; related to **[#695](https://github.com/axios/axios/issues/695)** and **[#6984](https://github.com/axios/axios/issues/6984)**)
- **Opt-in UTF-8 Basic auth usernames:** Added `transitional.encodeBasicAuthUsername: true` to UTF-8 encode `auth.username` in XHR/Fetch config resolution, matching the existing password encoding and allowing usernames beyond Latin-1. The option defaults to `false`, preserving XHR's legacy username bytes, existing pre-encoding workarounds, and Fetch's existing rejection of config usernames above U+00FF. Fetch's final UTF-8 header encoding, URL credentials, and Node HTTP authentication remain unchanged. Invalid UTF-16 still rejects with `ERR_BAD_OPTION_VALUE` in XHR/Fetch. This is an additive, non-breaking option with matching ESM/CommonJS declarations. (**[#11159](https://github.com/axios/axios/pull/11159)**)
- **Proxy bypass CIDR ranges:** Added IPv4 and IPv6 CIDR matching to `NO_PROXY`/`no_proxy`, including bracketed IPv6 and IPv4-mapped IPv6 normalization, while malformed ranges fail closed. A `/0` entry bypasses the proxy for its entire address family.
- **HTTP status code names:** Added the RFC 9110 names `HttpStatusCode.ContentTooLarge` for 413 and `HttpStatusCode.UnprocessableContent` for 422 across the runtime API and ESM/CommonJS declarations. The existing `PayloadTooLarge` and `UnprocessableEntity` names remain as deprecated aliases, and numeric reverse lookups retain their existing v1.x names for compatibility. (**#11082**, closes **#11066**)

## Bug Fixes

- **XHR progress cleanup:** Detach download and upload progress listeners when a request completes, fails, times out, or is canceled. Final progress callbacks that throw are reported asynchronously without skipping listener and cancellation cleanup, and reentrant cancellation remains safe. Preserve the asynchronous XSRF timeout cleanup and existing public API and types. This ensures deterministic teardown; it does not establish the cause of the memory growth reported in #5641. (**[#11225](https://github.com/axios/axios/pull/11225)**, related to **[#5641](https://github.com/axios/axios/issues/5641)**)
- **XHR adapter cookie access:** Read eligible XSRF cookies through the asynchronous Cookie Store API when supported, avoiding synchronous cookie access while preserving existing URI decoding, malformed-value handling, and fallback behavior. Cookie preparation shares the configured request timeout and cancellation lifecycle; late results cannot send canceled or expired requests. Fetch behavior, public options, and token values remain compatible. (**[#11166](https://github.com/axios/axios/pull/11166)**, closes **[#10826](https://github.com/axios/axios/issues/10826)**)
- **Node HTTP adapter - proxy tunnel TLS options:** Apply `https.globalAgent` TLS options, including a custom `ca`, to HTTPS origins reached through CONNECT proxies when no per-request `httpsAgent` is supplied. Read origin TLS options for each request so cached tunneling agents pick up changes to the selected agent or a replacement global agent. Explicit agents retain precedence, and the HTTPS proxy connection retains its existing TLS configuration. No new API or type changes. (**#11178**, related to **#11176**; the reported explicit-agent failure remains unverified.)
- **Percent-encoded Base64 data URLs:** Decode URL-escaped Base64 alphabet, padding, and whitespace before converting the Node HTTP adapter's data URL response. Estimate the Buffer backing allocation after the same decoding so encoded alphabet and padding no longer inflate byte-limit checks, while avoiding the per-character decoding scan for unescaped Base64. Ordinary Base64 inputs, forgiving Buffer decoding, and case-insensitive URL schemes and Base64 markers are preserved; pre-allocation limits still count ignored characters and content after padding. (**[#11294](https://github.com/axios/axios/pull/11294)**)
- **URL scheme casing:** Accept uppercase and mixed-case supported schemes in the XHR adapter and Node data URLs. Keep data URL allocation estimates aligned with decoding so configured limits reject oversized inputs before Buffer allocation, including ignored Base64 tails. URL paths, query values, payload casing, and unsupported-protocol rejection remain unchanged; no new API or type changes. (**[#11163](https://github.com/axios/axios/pull/11163)**)
- **Request handling consistency:** Preserve explicit multipart boundaries, configured Blob constructors, and encoded body limits across Fetch uploads. Keep direct connection pools tied to the configured Node agent's cleanup, connection hooks, and pool keys; reject unsupported pool or TLS-session lifecycle overrides with `ERR_BAD_OPTION_VALUE` instead of discarding them. Parameter merging now handles deep objects without recursive copying, respects serializer depth options, ignores replaced defaults, supports runtimes without symbol reflection, avoids evaluating reserved-name accessors during validation, and reports circular parameters as `ERR_BAD_OPTION_VALUE`. Form serialization preserves hidden array-like indexes and numeric field names that cannot be array indexes. Data URL errors and upload chunking retain their runtime-specific behavior. (**#11242**)
- **Fetch response size errors:** Preserve `ERR_BAD_RESPONSE` and the current request/config when a fetch response exceeds `maxContentLength` and the runtime wraps the stream failure, including when it drops the original cause. Clarify when custom `env.Response` constructors must accept tracked streams at runtime while preserving existing response limits and constructor signatures. (**#11179**)
- **TypeScript declarations:** Exposed the branded response-default marker type so consumers can emit declarations for helpers that forward Axios request response generics. (**#11116**)
- **Header matcher callbacks:** Bind function matchers passed to `AxiosHeaders.has()`, `delete()`, and `clear()` to the headers instance, matching the existing TypeScript declarations and allowing callbacks to use header methods through `this` ([#11216](https://github.com/axios/axios/pull/11216)).
- **Method-specific headers:** Added default header buckets for all supported methods and removed those structural buckets during request preparation, so `OPTIONS`, `PURGE`, `LINK`, `UNLINK`, and `QUERY` defaults apply only to matching requests instead of leaking as literal headers. (**#11096**)
- **Literal method-named headers:** Preserve literal request headers named `common` or after an HTTP method, including `Link`, instead of dropping them or merging them as defaults. Dates, Buffers, typed arrays, and custom class values now use normal header serialization. Defaults buckets are limited to plain/null-prototype maps and compatible `AxiosHeaders`, including instances from different package builds that provide the complete header-container interface; a matching tag and `toJSON` alone do not turn application objects into defaults buckets. Only matching method defaults apply. **Compatibility change:** arbitrary class instances used as defaults buckets must be converted to a plain map or `AxiosHeaders` first, otherwise they are serialized as literal header values. Bucket and brand reads exclude shared-prototype values; throwing brand or `toJSON` getters fall back to literal header serialization instead of aborting request preparation. No new API or type changes. (**#11156**; refines **#11096**)
- **Node HTTP adapter option errors:** Invalid custom DNS lookup addresses and invalid or unsupported `httpVersion` values, including non-coercible JavaScript types, now reject with `AxiosError` and `ERR_BAD_OPTION_VALUE` while preserving the request config for diagnostics. (**#11096**)
- **AxiosHeaders - header named `__proto__`:** Preserve this header under the safe case variant `__Proto__`, including raw header strings and normalization of padded names from objects, Maps, or arrays of pairs. Previously, string values were discarded and array values could replace the instance prototype and remove its methods. Fetch and XHR response headers now retain the value exposed by the platform, including repeated raw header lines. Header lookup remains case-insensitive, and copying the stored header onto a plain object preserves its value without invoking the prototype setter. Request config merging continues to filter `__proto__`, `constructor`, and `prototype`. (**#11134**)
- **Runtime configuration hardening:** Prevented values inherited only from shared prototypes, including another JavaScript realm's `Object.prototype` even when its `constructor` is altered, from becoming request behavior after config merging or interceptor replacement. Methods, headers, adapters, transports, FormData hooks, serializer options, and Fetch `Request` options are protected. Already-safe writable merged configs retain their identity through dispatch, while frozen, sealed, accessor-based, otherwise restricted, or unsafe-key-bearing replacements become writable filtered snapshots. Interceptor replacements with non-terminal application-defined prototypes remain supported as normalized null-prototype snapshots, terminal null-prototype ancestors are treated as shared boundaries to fail closed, and own `__proto__`, `constructor`, and `prototype` keys remain excluded from materialized configs.
- **Fetch adapter consistency:** Custom fetch implementations now receive the fully resolved `Request` plus a safe second `fetchOptions` argument that preserves custom own fields without overriding Axios-managed request fields. The authoritative method, headers, body, signal, duplex, and credentials are available on the `Request` and omitted from the second argument. `maxRedirects: 0` selects manual redirect handling when supported; Node exposes the unfollowed 3xx response, while browsers may expose an opaque redirect with status 0 and inaccessible headers. The no-`Request` fallback receives the same safe resolved options.
- **HTTP/2 adapter consistency:** Custom DNS lookup functions now apply to HTTP/2 connections and can reuse pooled sessions safely. Explicit Axios proxy objects fail with `ERR_NOT_SUPPORT`, while process-environment and HTTP/1-agent `proxyEnv` settings are ignored because `http2.connect()` cannot apply them; `proxy: false` continues to force a direct connection. Failed sessions are removed without leaking an unhandled session error.
- **HTTP/2 session pool:** Remove sessions from the pool immediately on `GOAWAY`, including before requests started inside a session's `goaway` callback can reuse the draining connection. Existing streams may finish, and their completion no longer schedules an idle timer for an already-removed session that could delay process exit. No public API or default changes. ([#11210](https://github.com/axios/axios/pull/11210))
- **Data URI validation:** Rejected media types containing extra slash separators and avoided excessive backtracking for long malformed media types.
- **Node HTTP adapter - keep-alive memory retention:** Reused a module-scoped socket error listener so pooled keep-alive sockets no longer retain the adapter context, response body, and buffers from the request that first used each socket. Socket errors continue to destroy only the currently active request. (**#11091**)
- **Data URLs - `;base64` token casing:** The Node HTTP adapter now accepts uppercase and mixed-case base64 markers, such as `data:text/plain;BASE64,SGVsbG8=`, instead of rejecting them with `ERR_BAD_REQUEST` (the internal helper raised `ERR_INVALID_URL`). The decoder and its allocation estimator recognize the same case-insensitive trailing marker, allowing payloads at `maxContentLength` while rejecting oversized Buffer allocations before decoding, including ignored input and percent-containing bodies. URL scheme casing, percent decoding, public APIs, and types are unchanged. (**[#11138](https://github.com/axios/axios/pull/11138)**)
- **XHR Adapter - final download progress delivery:** `onDownloadProgress` now always receives a final delivery when a completed XHR download reaches its successful `loadend` handler. The callback runs while that event is still dispatching, so listeners reading incremental data from `event.currentTarget` observe the complete response. Previously the final delivery happened only when a throttled progress event was still pending, and it replayed an event whose dispatch had already finished — `event.currentTarget` was `null` — so text-streaming consumers could lose every chunk after the first in browsers whose progress cadence kept deliveries inside the throttle window. A final callback that cancels the request stops settlement processing cleanly, while a throwing callback does not leave the request pending. Upload progress and flushes triggered by stream errors, abort reasons, or failed XHR downloads retain their prior pending-event behavior. (closes **#6796**)
- **XHR Adapter - navigation-canceled requests:** A response that reaches `loadend` with status 0 is now rejected as an `ECONNABORTED` error instead of resolving as a success with an empty body. Firefox 152 stopped firing `error` and `abort` for requests canceled by a document navigation, leaving `loadend` as the only handler that runs, so those requests were settling as successful responses. Rejecting with `ECONNABORTED` matches what `onabort` raised on Firefox 151, so the outcome an application sees is unchanged by that update. Reads over `file:`, which some environments report as status 0 on success, still resolve, whether the scheme appears on the request URL, is inherited from a `file:` page origin by a relative request URL, or appears only on `responseURL`. Because no response was received, the rejection is not suppressed by `validateStatus`, matching how `onerror` and `onabort` already behave. (**#11094**, closes **#11093**)
- **Request error stacks:** Preserved original request failures when custom `Error` stack instrumentation returns non-string data or throws during optional stack decoration. (**#11109**, closes **#11108**)
- **Request error stacks:** Restored appending of one- and two-frame reconstructed request stacks when they are not already present, preserving caller context when the runtime captures it. Duplicate suppression and protection against failing custom stack hooks remain unchanged; the runtime's stack capture limit is not increased. (**#11132**, closes **#11131**)
- **Fetch adapter - cache mode:** Omitted the implicit `cache: 'default'` when a runtime rejects it but accepts a request without a cache option, restoring requests on Cloudflare Workers, including older compatibility dates and `cache_option_disabled` configurations that reject every explicit cache mode. Supporting runtimes retain the explicit default to protect against `Object.prototype` pollution, and caller-supplied cache options remain unchanged. (**#11194**, closes **#11192**)
- **Interceptor storage:** Removed trailing interceptor tombstones after ejection so repeated register-then-eject cycles no longer grow the handlers array, while preserving its public array shape, interceptor iteration behavior, and interceptor ID identity across registrations. (**#11070**)
- **Wrapped error stacks:** `AxiosError.from()` now appends an available wrapped error stack to `error.stack` under a `Caused by:` section for reporters that only read stack strings. Reconstructed request/caller frames stay ahead of the cause, including one- and two-frame stacks, without being duplicated on repeated rejection or confusing marker-like text in messages with the appended section. `error.cause` remains unchanged and non-enumerable; missing, empty, non-string, throwing, or unwritable stacks do not make optional decoration fail error normalization. Each wrap adds one nested section, so repeated wrapping increases stack size. This does not reveal network details withheld by browsers. (**[#11142](https://github.com/axios/axios/pull/11142)**, relates to **[#6670](https://github.com/axios/axios/issues/6670)**)
- **Interceptor ID compatibility:** Restored `eject(String(id))` removal after interceptor storage moved to a Map, including registrations made after trailing handlers have been compacted. Empty, noncanonical, unknown, and stale IDs remain no-ops. The documented numeric-ID API and TypeScript declarations are unchanged. Existing nullish-handler tolerance and automatic recovery on `use()` from #11118 are preserved. (**[#11139](https://github.com/axios/axios/pull/11139)**, follows up **[#11114](https://github.com/axios/axios/issues/11114)**)
