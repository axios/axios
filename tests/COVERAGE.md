# E2e coverage audit

## Baseline and method

The migration audited the repository at `d491e0e15724e5b02a3331ffebc29aa1c33fc606` on `v2.x` (2026-10-22). The inventory covers 193 JavaScript/TypeScript files in the source and consumer test trees, 39,354 lines, and 1,868 static test/suite titles. Parameterized tests expand beyond those static titles. Existing unit, source-browser, setup, and artifact files remain unchanged.

The public GitHub issues API was paginated without a date cutoff or search-result limit, using `state=all&per_page=100&sort=created&direction=asc`. Screening covered all 7,972 accessible issue/PR titles and opening bodies through #11363: 5,085 issues and 2,887 PRs, including 7,858 closed and 114 open records. Topics were cross-referenced with the test inventory, existing issue references, supported runtimes, and the current package contract. Focused regression reports and the current implementation were then inspected for concrete end-to-end scenarios.

This is a public title/body audit. It does not establish a manual review of every historical comment, attachment, or PR diff; private advisory material was not fetched. Closed and open reports can describe unsupported usage or fixes that have not landed, so a report alone is not evidence of an Axios defect. The rows below identify the historical reports that influenced the executable scenarios or the retained lower-level coverage.

## Coverage retained in source tests

Prototype-pollution guards, malformed configuration, adapter capability probes, custom environment constructors, helper-only APIs, many cancellation-reason edge cases, and exact event-order races retain their existing focused tests. E2e complements these with real I/O. The old consumer suites' mocked transport and adapter-echo assertions are removed; their relevant consumer behavior is represented above.

React Native/mobile WebViews, Cloudflare/workerd, Electron-specific integrations, historical ES5/older-Node support, every browser navigation lifecycle, every HTTP/2 GOAWAY timing race, and all operating-system/proxy combinations are not claimed as covered by this initial e2e matrix. For example [#11192](https://github.com/axios/axios/issues/11192) requires workerd to prove that platform's behavior; a Node Fetch mock is insufficient. Existing unit/capability coverage is retained and these remain explicit expansion targets.

## Defects found by real-network checks

The initial unpatched tarball failed native Fetch FormData content-type and custom timeout-message scenarios. The expanded scenario also demonstrated that a declared response-length rejection left an unfinished server response open ([#11292](https://github.com/axios/axios/issues/11292)). Focused runtime fixes accompany the new failing-before/passing-after e2e coverage. Existing unit tests remain unchanged; a new focused unit file also checks custom response-body cancellation that throws, rejects, or never settles, preserving prompt rejection with the original size error and no unhandled cleanup rejection. These exceptional custom-environment cases belong in unit tests; the e2e transport remains native.
